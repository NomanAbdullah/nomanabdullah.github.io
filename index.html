Compilers make code fast. I study when they make it wrong.

I’m a PhD student in Computer Science at Baylor University, studying how compiler optimizations interact with undefined behavior, security bugs, and programmer assumptions in C programs.

About

I work with Dr. Mengfei Ren at Baylor University on compiler correctness and security. Compilers sit underneath nearly every piece of software, so a single wrong optimization can break or weaken thousands of programs that were written correctly. My research asks which optimizations go wrong, why, and how we can catch them before they ship.

Before graduate school I spent five years as a security engineer, first in R&D at Quantei and then at Wazuh, where I wrote technical content for its open-source security platform. Those years taught me to focus on problems that show up in production, not just in benchmarks.

I've studied in Sri Lanka, Russia and the United States, and I speak Bengali and English.

Research

Bugs introduced by compiler optimization

When does making a program faster make it incorrect?

I study real optimization bugs in GCC and LLVM to understand which passes fail and how, then build techniques to detect them automatically in C compilers.

Security consequences of compilation

Can a correct compiler still make code less safe?

Optimizations that are legal under the C standard can remove safety checks or expose memory errors. I work on static analysis and security-preserving optimization so performance doesn't come at the cost of safety.

AI-assisted security analysis

How can machine learning help teams ship secure code?

I've built ML-based security analysis for DevSecOps pipelines and earlier worked on deep-learning detection of deepfake audio.

I'm also interested in the security of large language models and multi-agent AI systems.
